# M23 P8.1 — Full lifecycle attack surface

Every stage of the recruitment journey and every act that moves it, read as an
attacker would (§2, §3). One row per lifecycle state (the frozen 18) plus the
resource sub-states each domain keeps. "Writer" is the ONE code path that may
change the thing; "coverage" names the suites that already prove the row and
the P8.1 hardening group (`m23RecruitmentJourneyHardeningE2E`, letters A–Z)
that attacks it.

## 2. Resource sub-states

| Resource | States | Writer | What a stale or corrupt state may never do |
| --- | --- | --- | --- |
| Contact | draft → delivered → responded; draft → failed; any → cancelled; external `recorded` | m23/contactRoutes (one writer, `expectedRev` on every mutation) | a draft or failed Contact never proves `contacted`; a cancelled one is never current; a Contact of another case never counts here |
| Trial request | pending → accepted / declined / withdrawn / expired | `issueRecruitmentRequest` (the ONE request writer) | a request without `caseId` proves nothing; a declined one is not a Trial |
| Trial | invited → accepted → scheduled → completed; cancelled; legacy_accepted (no schedule); `subjectRemovedAt` | m23/trialRoutes (`expectedRev`) | an accepted Trial is not scheduled; scheduled is not completed; another case's Trial is omitted |
| Assessment | draft → submitted | M12 | a draft never counts |
| Decision | draft → final (formal / advisory); superseded (`supersededById`) | m23/decisionRoutes; M17 advisory | a draft or superseded row is never the head |
| Offer revision | DRAFT → ISSUED → ACCEPTED / DECLINED / WITHDRAWN / EXPIRED (derived) / SUPERSEDED | m28 (`expectedRev` required on club mutations; named `revisionId` on answers) | a superseded, withdrawn or expired revision is never answerable; a new DRAFT beside a live revision is discarded by the recipient's answer |
| Signing package | DRAFT → READY → IN_PROGRESS → COMPLETED; CANCELLED; VOIDED; EXPIRED (derived); superseded revisions | m29 (`expectedRev`, named revision + document digest on every signature) | an expired or superseded package never masks a live one; a completion without every party is refused; a completion whose lifecycle move fails rolls back whole |
| Signing row (`db.signings`) | standing; cancelledAt / revokedAt / voidedAt | m29 `recordCompletedSigning` (canonical and legacy) | one row per package and per Offer; one standing legacy row per club + player (P8.1); a row that predates the case proves nothing for it |
| Contract status | `under_contract` (m29 only) / self-declarable words (player route, refused while a canonical contract stands) | m29; the player route; squad release (guarded) | the player, the guardian and squad housekeeping never write `under_contract` |

## 3. Cross-cutting dependencies

| Dependency | Where it is decided | Attack | Answer |
| --- | --- | --- | --- |
| Role | `roomRole(room, user, isLead)` on every request from the live user row; `removedAt` ends sessions and streams | role removed while a tab is open | the next request is refused (`ROOM_PERMISSION_REQUIRED` / `LIFECYCLE_NOT_PERMITTED`); the strip re-reads and drops the control (live C) |
| Org membership | `orgAuth`: session → org → user, `removedAt`, `suspended` | removed user keeps a token or a stream | 401 `USER_REMOVED`; sessions deleted; SSE closed on removal |
| Agent authority | `integration.decide` / `basisFor` / `licenceCurrentFor` on every read; `findOwnAgreement` | expiry, termination, licence lapse, affiliation loss, scope change, block | the journey read answers 403 with the rule; deep links open nothing (F7, live G7; hardening K) |
| Block | `isBlocked(playerId, orgId)` at every send / issue / start / completion and on every discovery read | block landing mid-stage | the next act refuses; history stays; closure acts (withdraw, cancel, void, report) stay (M23_P81_BLOCK_TRANSITION_MATRIX.md) |
| Minor | `isAdult` (unknown / malformed DOB → not adult) at every recipient resolution; `minorOfferPathwayOpen` / `minorSigningPathwayOpen` closed | malformed DOB | fails closed (hardening M) |
| Temporal | `parseStrictDateOnly`, finite-instant guards in the model, the funnel and the timeline | NaN, Infinity, out-of-range | TEMPORAL_ORDER; omitted from intervals; never re-ordered (hardening R, T) |
| Idempotency | per-resource key rows with fingerprints; every route authorizes before it looks a key up | key replay after authority loss or supersession | authorization first (a removed role meets 403 before the key); a signature key dies with its revision (D-P81-12) |
| Rate limits | one limiter, budgets per org / actor; legacy routes now draw on the canonical budgets (D-P81-4) and dedupe (D-P81-3) | aliasing through an old route; flooding the bucket store | same budget; eviction never resets live budgets (D-P81-5) |
