SCOUTBOX THEME KIT

The Player app uses React Native SVG and its existing theme provider. Its
implementation is updated separately; do not insert these browser styles or
theme.js into the native app. These files are reusable web equivalents.
The logo font is untouched. UI text uses the system font stack: SF Pro on Apple
and native sans elsewhere. Do not bundle Apple font files. Retain the wordmark.

CSS:
Use sb-app sb-canvas together on the page shell for the multicolour background.
The neutral sb-app alone is available for utility pages. No embossed pitch pattern.
Use sb-app sb-canvas together on the page shell for the multicolour background.

Load theme.js in the document head before theme.css (non-deferred script).
Player is dark-only. CSS paints dark even without JavaScript; theme.js fixes
browser form controls to dark. Saved light preferences and OS mode are ignored.
ScoutBoxTheme.getPreference() returns 'dark'; there is no theme setter or toggle.
Do not add an appearance selector. This applies to Player only.

Update the visible width and aria-valuenow together using finite values 0–100.
Never use a decorative stat animation to fabricate a real progress measure.
Use native disabled on buttons; aria-disabled alone does not disable actions.
For tabs, implement the proper tablist/panel relationships and keyboard behaviour.

TAILWIND v3:
Use tailwind-v3.config.cjs with your existing Tailwind directives, then import
(or link) theme.css. The same arbitrary-value examples work; replace
focus-visible:outline-3 with focus-visible:outline-[3px]. The v3 config also
provides bg-sb-action and bg-sb-progress shortcuts.

CONTRAST:
The approved dark gradient uses exact 135-degree #00E676 → #12161A stops.
Cyan #00C8FF is the supporting accent. Dark controls add a 55% black scrim
for white-label contrast; raw unlabelled progress graphics retain their stops.
Keep carbon surfaces and subtle green/cyan glows, without a pitch pattern.
